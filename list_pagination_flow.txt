二、两个数值参数的取值规则
--------------------------------------------------------------------------------

共同点：都先去除两端空白，只接受 ASCII 数字 0-9 组成的字符串，允许
前导零，数值上限为 9223372036854775807（SQLite 有符号 64 位整数上限，
SQLITE_INT64_MAX，cli.py:34-35）。不同点：--after-id 允许零（与省略
等价），--limit 只允许正整数。

1. --after-id：非负整数，0 与省略等价
   [代码] validate_after_id（cli.py:134-153）：
   - raw_after_id.strip() 去两端空白（cli.py:141）；
   - re.fullmatch(r"[0-9]+", ...) 要求整串为 ASCII 数字（cli.py:142）：
     空串、纯空白、负数 "-1"、带正号 "+1"、小数 "1.5"、内部空白
     "1 2"、非 ASCII 全角数字 "１２" 均不匹配，返回 ("invalid", None)；
   - 去前导零后为空串（"0"、"000" 等全零）即边界 0，返回 (None, 0)，
     与省略参数等价（cli.py:144-147）；
   - 去前导零后位数多于上限、或位数相同而字典序更大（如
     9223372036854775808），返回 ("invalid", None)（cli.py:148-152）；
     该比较在字符串上完成，不调用 int()，任意长的数字串都不会触发
     Python 的转换限制；
   - 其余返回 (None, 对应整数)（cli.py:153）。
   [测试] test_list_after_id.py:154-161（前导零 "0001" 被接受）、
   163-170（两端空白 "  1\t" 被去除）、134-144（"0"/"000" 与省略
   等价）、226-240（非法输入矩阵逐字断言
   '{"errors":{"after_id":"invalid"}}\n'）；均未运行。

2. --limit：正整数，不允许零
   [代码] validate_limit（cli.py:112-131）：与 after_id 相同的
   strip、[0-9]+ 整串匹配、上限比较；唯一区别是全零（"0"、"000"）
   不是正整数，返回 ("invalid", None)（cli.py:122-125）。
   [测试] test_list_after_id.py:242-259 在合并错误用例中以
   --limit 0 断言 limit 的 invalid；更完整的 limit 规则见
   test_list_limit.py；均未运行。

3. 等号写法
   [代码] 两个参数都由 argparse 按常规选项解析（cli.py:752-759），
   --after-id=1 与 --after-id 1 等价。
   [测试] test_list_after_id.py:172-177（--after-id=1）；未运行。

--------------------------------------------------------------------------------

1. 编号边界与既有筛选取交集

五、固定样例与两次独立进程的翻页示例（本次已实际执行）
--------------------------------------------------------------------------------

样例沿用 test_list_after_id.py 的固定夹具（test_list_after_id.py:
27-32 的类 docstring 与 34-50 的 setUp）：
  id 1 林晓  lin@example.test   测试工程师  applied  已有评价
  id 2 周宁  zhou@example.test  测试工程师  applied  无评价
  id 3 陈禾  chen@example.test  开发工程师  applied  无评价

建立前置数据的命令（每条都是独立进程）：
  python -m recruiting --db demo.sqlite3 add \
    --name "林晓" --email lin@example.test --position "测试工程师"
  python -m recruiting --db demo.sqlite3 add \
    --name "周宁" --email zhou@example.test --position "测试工程师"
  python -m recruiting --db demo.sqlite3 add \
    --name "陈禾" --email chen@example.test --position "开发工程师"
  python -m recruiting --db demo.sqlite3 add-feedback --id 1 --text "林晓的评价"

翻页条件：全岗位（--all-positions）、无评价（--without-feedback）、
每页一条（--limit 1）。满足条件的只有 id 2、3，按 id 升序。

第一页（不带边界）：
  python -m recruiting --db demo.sqlite3 list \
    --all-positions --without-feedback --limit 1
[实跑] 退出码 0，stderr 为空，stdout 单行：
  [{"id": 2, "name": "周宁", "email": "zhou@example.test", "position": "测试工程师", "stage": "applied"}]
即首页命中周宁，取走其 id 2 作为下一页的边界。

第二页（以上一页末条 id 为 --after-id，同一数据库、新的独立进程）：
  python -m recruiting --db demo.sqlite3 list \
    --all-positions --without-feedback --after-id 2 --limit 1
[实跑] 退出码 0，stderr 为空，stdout 单行：
  [{"id": 3, "name": "陈禾", "email": "chen@example.test", "position": "开发工程师", "stage": "applied"}]
边界 2 排除了林晓（id 1，本无评价条件也不命中）与周宁（id 2）本身，
按 id 升序的第一条命中是陈禾。

第三页（边界越过末条）：
  python -m recruiting --db demo.sqlite3 list \
    --all-positions --without-feedback --after-id 3 --limit 1
[实跑] 退出码 0，stderr 为空，stdout 为：
  []
边界越过最后一条命中时得到空数组——这就是“已翻完”的信号，不是错误。

说明：每个对象仍含 id、name、email、position、stage 五个既有字段
（cli.py:31、233）；以上三条查询均为成功路径，退出码 0、stderr 为空。
[测试] 同一样例下 test_list_after_id.py:201-215 断言无评价者边界 1
之后为 id 2、3 且 limit 1 只取 id 2；未运行。

六、一致性与落盘约定
--------------------------------------------------------------------------------

1. 数据未变化时，重启后结果一致
   [代码] 每次进程都重新 connect 同一文件并执行同一条 SELECT
   （cli.py:835、232），查询结果完全由当前库内容决定；两次相同查询
   之间若无写入，输出逐字节相同。
   [实跑] 第五节的三条查询在同一临时库上重复执行，输出一致。
   [测试] test_list_after_id.py:314-319 用两次独立命令调用断言
   stdout 完全相同；未运行。

2. 每次查询读取当前数据，不保证跨查询快照
   [代码] cmd_list 在单次连接内执行一条 SELECT（cli.py:232），进程
   结束连接即关闭（cli.py:839）。两次独立的 list 调用之间没有任何
   事务或快照把数据“钉住”：若另一进程在两次翻页之间增删改了候选人
   或评价，第二次查询看到的就是新的当前数据，可能出现记录跨页重复
   或遗漏。编号分页只保证“同一时刻的数据按 id 升序、边界严格排除”，
   不保证翻页序列整体对应某一历史快照。

3. “不改业务记录”不等于“完全不落盘”
   [代码] list 本身只读：cmd_list 没有任何 INSERT/UPDATE/DELETE
   （cli.py:156-235），失败路径在 SELECT 之前返回（cli.py:188-190）。
   但 main 中的 connect（cli.py:835 → 60-65）会先执行
   CREATE TABLE IF NOT EXISTS 并 commit：数据库文件不存在时会创建
   该文件，表缺失时会补齐空表。
   [实跑] 对一个不存在的路径只运行 list 系列命令后，该路径出现了
   约 20KB 的 SQLite 文件（含三张空表）。
   [测试] test_list_after_id.py:304-312 以“全部记录列表前后一致”
   断言成功与失败查询都不改动业务数据；其口径是业务记录不变，与
   上述建库建表行为并不矛盾；未运行。
